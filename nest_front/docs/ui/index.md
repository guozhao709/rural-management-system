# UI Design Documentation

本目录用于定义项目的 UI 设计规范。

项目包含两套相互关联但必须明确区分的 UI System：

* **User UI**：面向普通用户的移动端界面，文件：`/nest_front/docs/ui/userUI.md`
* **Admin UI**：面向管理员的 PC 中后台界面，文件：`/nest_front/docs/ui/adminUI.md`

两端共享智乡云的品牌基础，但在布局密度、交互方式、视觉表现和组件设计上存在明显差异。

---

## 1. UI 文档入口

### 用户端

适用于：

* 移动端用户页面
* 用户首页
* AI 服务
* 农业服务
* 健康服务
* 天气与便民服务
* 用户个人中心
* 其他面向普通用户的页面

读取：

```text
/nest_front/docs/ui/userUI.md
```

用户端核心方向：

> HarmonyOS 风格的移动端服务 UI，强调简洁、自然、圆润、易读和低认知负担。

---

### 管理员端

适用于：

* 管理后台
* 用户管理
* 内容管理
* 农业数据管理
* 健康数据管理
* AI 服务管理
* 系统配置
* 数据统计
* 其他面向管理员的 PC 页面

读取：

```text
/nest_front/docs/ui/adminUI.md
```

管理员端核心方向：

> 现代轻量化 PC 中后台 UI，强调专业、清晰、高效和较高的信息密度。

---

## 2. Agent 使用规则

Agent 在执行任何 UI 相关任务前，必须首先判断当前页面属于：

```text
User
```

或：

```text
Admin
```

然后只读取并遵循对应的 UI 规范。

禁止：

* 使用管理员端规范设计用户端页面
* 使用用户端规范直接设计管理员端页面
* 将两端的字号、圆角、布局密度、组件形式直接混用
* 因组件库默认样式而突破对应 UI 规范

如果当前任务同时涉及 User 和 Admin，则必须分别按照各自的 UI 规范进行设计。

---

## 3. 两端共享内容

User UI 与 Admin UI 不是两套完全独立的品牌。

两端共享：

* Brand Primary Color
* 基础品牌识别
* 状态颜色
* 业务辅助色
* 字体体系
* 基础 Icon 风格
* 智乡云整体品牌气质

但不共享具体的：

* 页面布局
* 信息密度
* 圆角尺度
* 组件尺寸
* Table / Form 表现
* 移动端交互模式
* PC 中后台交互模式

因此：

> **品牌保持统一，界面体系保持分离。**

---

## 4. 页面级设计

本目录中的 UI 文档主要定义：

* Color System
* Typography
* Visual System
* Spacing
* Radius
* Icon
* Motion
* Interaction
* Accessibility

具体页面的：

* 信息架构
* 页面布局
* 数据展示方式
* 功能区域划分
* 业务组件组合

应在开发对应页面时根据业务需求单独设计。

不得因为 UI 规范中没有规定具体页面布局，就自行突破已有 Design System。

---

## 5. 判断原则

如果无法确定应使用哪套 UI 规范，按照实际使用者判断：

```text
普通用户 / 村民
    ↓
User UI

管理员 / 运营人员 / 系统维护人员
    ↓
Admin UI
```

不要根据技术模块、路由名称或组件库判断 UI 类型。

最终判断依据始终是：

> **这个界面是谁在使用。**
