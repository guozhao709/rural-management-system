# 前端验证规范

本规范适用于 `nest_front/admin` 和 `nest_front/users`。验证工具与命令长期维护；具体业务场景和验收标准随需求补充。

## 配置归属

- `nest_front/eslint.config.mjs`：两端共享 JavaScript、TypeScript 与 Vue essential 静态规则，应用根配置显式引用它。Lint 不承担统一排版职责。
- 各 SPA 的 `tsconfig*.json`：检查源码、组件测试、Vite/Vitest/Playwright 配置及 E2E TypeScript。
- 各 SPA 的 `vitest.config.ts`：合并本应用 Vite 配置，使用 jsdom；仅收集 `src/**/*.spec.ts`、`src/**/*.spec.tsx`，不混入 Playwright 场景。
- 各 SPA 的 `playwright.config.ts`：收集 `e2e/`，默认无头 Chromium；管理员端采用桌面视口，用户端采用移动端模拟。模拟视口不等于真实设备验收。
- 依赖版本以包声明和根锁文件为准。公共工具配置不属于业务层，不允许借此跨 SPA 导入业务源码。

## 命令

以下命令在所选 SPA 目录执行；依赖从仓库根目录安装，见 [开发入口](../../../docs/development/index.md)。

| 命令 | 用途 | 副作用或前提 |
| --- | --- | --- |
| `pnpm typecheck` | Vue 与 TypeScript 类型检查 | 写入增量缓存，无应用构建输出 |
| `pnpm lint` | 静态规则检查，警告也导致失败 | 不修改源文件 |
| `pnpm lint:fix` | 修复可自动处理的问题 | 会修改文件，仅用于任务涉及范围 |
| `pnpm build` | 类型检查与生产构建 | 写入 `dist/` |
| `pnpm test` | 单次组件与单元测试 | 不启动真实浏览器或后端 |
| `pnpm test:watch` | 本地交互式测试 | 持续运行，不用于无人值守验收 |
| `pnpm test:cov` | 单元测试与覆盖率报告 | 写入 `coverage/`；数值不代替行为验收 |
| `pnpm test:e2e:install` | 安装当前 Playwright 对应的 Chromium | 首次或 Playwright 升级后执行；需要网络和浏览器缓存写权限 |
| `pnpm test:e2e` | 真实浏览器交互验证 | 自动管理前端服务，写入测试报告与失败证据 |
| `pnpm dev:e2e` | E2E 专用前端服务 | 由 Playwright 自动调用；仅监听本机测试端口 |

浏览器安装在同一机器上可由两个应用复用。E2E 使用独立端口 6173/6174，不复用未知的已有服务，端口占用时失败。默认零重试，失败不自动掩盖；报告位于应用的 `playwright-report/`，失败截图和 trace 位于 `test-results/`，分享前需检查敏感数据。

在受限 Agent 环境中，浏览器安装需要缓存目录写权限，Windows E2E 还需要结束自身服务进程树的权限。若用例结束后服务清理被阻止，应报告环境限制并在获准的执行环境重跑；只有整条命令正常退出才报告该命令 PASS，不以关闭端口检查或复用未知服务规避问题。

当前模板交互用例用于证明组件挂载、事件、实例隔离、页面装配和重新加载可验证。替换模板时同步替换为真实功能用例，不长期保留仅为门禁通过而存在的模板页面。

## 按变更选择验证

适用 AGENTS 中的 Required 检查必须执行；Conditional 按以下影响判断，而不是任意省略：

- 新增或改变纯逻辑、状态分支、输入边界：执行相关单元测试；可稳定复现的 Bug 补回归测试。
- 改变组件 Props/Emits、表单、条件呈现或状态交互：执行相关组件测试。
- 改变用户可见交互、路由、加载和错误状态、响应式布局或浏览器 API：执行相关浏览器验证；jsdom 不能证明真实布局与浏览器行为。
- 改变共享组件或公共逻辑：检查受影响调用方并执行相应回归；影响可见行为时加入浏览器验证。
- 改变路由懒加载、构建配置或依赖：执行类型检查、Lint、Build 和受影响的测试；涉及运行时加载时执行浏览器验证。
- 改变认证、授权或 API 契约：同时检查后端 Provider 与前端 Consumer；仅隐藏 UI 或 Mock 响应不能证明安全边界。
- 纯文档变更：检查内容、路径和引用，不要求无关应用测试。

测试数据可以使用明确的 Fixture/Mock，但必须报告替代了哪些外部边界。缺少后端、真实设备或外部服务时，分别记录自动化结果和未完成的验收，禁止将未执行项计为 PASS。

当前需求未指定统一覆盖率阈值，不自行设定业务验收门槛；新增业务时优先覆盖边界、异常和可观察行为。禁止通过排除实际业务源码、削弱断言或关闭检查使报告变绿。
