# M09 Codex 实施提示词

你是本项目的主实现代理。请在当前工作区内持续实施 **M09 健康评估与健康知识 P0**，直到工程范围内可以安全完成的工作全部完成、自动化质量门禁通过，或出现必须由用户提供新权限/外部专业结论才能继续的真实阻塞。

你的任务是修改代码、迁移、测试和文档，不是再次输出一份设计建议。完成一次检查后继续执行下一步，不要停在“我建议接下来……”或只给伪代码。

## 2. 目标边界

实现 `方案设计.md` 第 3.1 节定义的 P0，并满足第 20 节全部完成标准。范围包括：

- `nest_server` 中的 M09 后端、配置、Migration、Seed/导入工具、测试和文档。
- `front-end/users` 中健康页面、API 类型、交互和结果展示的 P0 迁移。
- M07 所需的公共健康知识内部 Facade 契约；M07 尚未实现时只提供清晰、可测试的导出边界。
- 与用户删除/注销相关的 M09 清理契约；不要借机重构无关模块。

P1/P2 只保留可演进边界，不实现设备接入、在线问诊、电子处方、医务人员工作台、完整消息队列或复杂权限系统。

业务定位固定为：**健康信息记录、风险分层、就医引导和权威健康科普**。产物中的命名、Schema、API、页面和文案都应体现该定位。

## 3. 硬性安全规则

以下规则优先于进度和兼容性：

1. 用户身份只取 `UserAuthGuard` 注入的当前用户，健康 DTO 不接受 `userId`、手机号或年龄作为所有权依据。
2. 档案、测量、评估和删除查询同时包含资源 ID 与当前 `user_id`；跨用户资源统一返回 404。
3. 新 Schema 和页面不包含疾病概率、具体药品、剂量、处方建议或模型自行决定的紧急标志。
4. 非法模型输出、信息不足、规则缺失和上游失败采用 fail-safe：返回 `insufficient` 或明确错误，绝不回落成低风险。
5. 安全分诊先于模型。模型只能解释，不能降低规则给出的就医紧迫度；紧急提示不能等待模型完成。
6. 不自行编造医学阈值、临床规则、审核人、医疗资质或专业验收记录。
7. 没有已批准规则集时实现并启用 `UnavailableSafetyTriageAdapter`，保持个性化评估关闭；健康知识、档案和测量仍可运行。
8. AI 说明必须通过 Zod 和安全后置校验，带显式 AI 标识、知识引用、局限和非诊断说明。
9. M07 默认只能检索已发布公共知识，不能查询任何用户档案、测量、症状或评估历史。
10. 健康敏感字段以带认证的应用层加密落库并记录密钥版本。日志、指标、错误和审计记录不包含健康正文、Prompt 或模型原文。
11. 缺少健康密钥、规则或 LLM 配置不能拖垮认证、用户、农业和公共健康检查；按功能开关明确禁用相应能力。
12. 健康知识 Seed 只能使用可核验的官方一手来源，默认进入草稿/待审核状态。AI 生成内容不能自动发布为健康知识。

- 必须修改共享文件时，先读取当前内容，做最小增量合并，再运行相关回归测试。
- 未经用户要求不创建提交、不改写历史、不推送远端。

先运行现有可执行的质量命令建立基线。若基线已经失败，记录完整命令、失败原因和是否与 M09 无关；仍继续完成可安全隔离的 M09 工作。最终报告必须区分预存失败与本次引入失败。

## 5. 进度与假设文件

首次执行时创建并持续维护：

- `nest_server/docs/M09/progress.md`
- `nest_server/docs/M09/ASSUMPTIONS.md`
- `nest_server/docs/M09/实施调整.md`

### `progress.md`

把 `方案设计.md` 第 19 节的 32 个最小任务一一映射为稳定 ID `M09-001` 至 `M09-032`。每项保持单一职责并记录：

- 状态：`PENDING`、`IN_PROGRESS`、`AUTOMATED_PASSED`、`EXTERNAL_REVIEW_REQUIRED`。
- 完成证据：修改文件、测试名称/命令、Migration 或可检查输出。
- 未完成原因和下一步。

同一时刻只允许一个任务为 `IN_PROGRESS`。只有完成标准和对应自动化证据都满足时才能标记 `AUTOMATED_PASSED`。需要医学、法务、真实模型或生产环境证据的项目标记 `EXTERNAL_REVIEW_REQUIRED`，不得伪装成自动化通过。

### `ASSUMPTIONS.md`

每项不确定性记录：假设、保守默认值、依据、验证状态、配置入口和未来替换路径。优先采用 `方案设计.md` 第 21 节的保守默认值；能配置的内容不散落为业务常量。

普通可逆假设不阻塞开发。只有会改变医疗安全边界、造成不可逆数据迁移、需要真实凭据或需要用户授权外部操作时才向用户询问。

### `实施调整.md`

只记录方案与实际实现之间有意义的差异：发现的代码事实、所选方案、替代方案、原因、影响和后续条件。不要把普通文件清单复制进来。

只有用户或仓库指令明确启用多代理时才允许委派。启用后，主代理是 `progress.md` 的唯一写入者；代理只能按加密/隐私、知识治理、评估流水线、前端等责任边界分工，不按机械任务数量拆分。共享文件和 Migration 由主代理整合。

## 6. 实施顺序

按以下阶段推进。每个阶段结束时运行该阶段的定向测试并更新进度，再进入下一阶段。

### 阶段 A：基线与骨架

1. 完成工作树、依赖、数据库、现有测试和 M08 共享改动审计。
2. 根据 32 项任务建立进度和假设文件，不能把未实现项预先标记完成。
3. 新增 `src/modules/resident-health`，保留现有 `src/health` 作为系统存活/就绪模块，避免名称冲突。
4. 新增条件配置、环境校验和 AppModule 接线。M09 默认安全关闭，公共知识读取是否开放使用独立、明确配置。

完成标准：应用在 M09 禁用、缺少健康密钥/规则/LLM 时仍可通过既有启动和装配测试；业务模块没有与系统 `HealthModule` 混淆。

### 阶段 B：同意、加密与健康档案

1. 实现 Consent Entity、Migration、状态规则和本人接口。
2. 定义 `HealthSensitiveDataCryptoPort`，提供生产 AES-GCM/等价带认证加密适配器和确定性测试适配器；生产配置不得使用硬编码密钥。
3. 实现一对一健康档案、Presenter、DTO、部分更新和显式清空语义。
4. 年龄从用户生日计算；`unknown` 与 `none` 分开表达。

完成标准：数据库约束、密文落库断言、错误密钥/篡改失败、同意撤回和 A/B 用户隔离测试通过，日志中没有敏感正文。

### 阶段 C：健康测量

1. 使用 Zod discriminated union 定义 P0 五类测量及固定单位。
2. 实现追加式 Measurement Entity、Migration、创建、分页、趋势和本人删除。
3. 区分测量时间、录入时间和来源；输入错误校验不冒充医学异常判断。

完成标准：合法/非法单位、未来时间、过旧时间、极端输入、分页顺序、趋势时间桶和跨用户访问测试通过。

### 阶段 D：健康知识治理

1. 实现 Article/不可变 Version、来源、适用人群、状态、审核和复核日期。
2. 实现 Admin 草稿/送审、Super Admin 发布/归档以及用户已发布知识检索。
3. 编辑已发布内容时创建新草稿版本，旧发布版本持续服务至原子切换。
4. 实现幂等 Seed；抓取或整理资料时只使用国家卫健委、国家疾控局、中国疾控中心、国家药监局等官方一手来源，保存 URL、发布日期、抓取/整理日期和内容哈希。

完成标准：缺来源或专业审核信息不能发布；过复核期内容不进入新评估；用户不能读取草稿；Seed 重复运行不产生重复内容。没有真实专业审核人时所有种子保持草稿，并在进度中标记外部审核。

### 阶段 E：安全分诊、AI 说明与评估历史

1. 定义 `SafetyTriagePort`、Unavailable Adapter、规则版本契约和规则合并纯函数。
2. 定义评估 DTO、状态、加密输入快照、知识引用快照和结果 Zod Schema。
3. 定义 `HealthExplanationLlmPort`，实现 Unavailable Adapter；复用并抽取现有 OpenAI 兼容基础设施时保持农业行为不回归。
4. 构造版本化 Prompt，严格分隔系统规则、公共知识和用户数据；发送前去除姓名、手机号、地址和内部 ID。
5. 实现安全后置校验：拦截疾病概率、具体药品/剂量、处方语气、缺少 AI 标识和规则降级。
6. 实现创建、列表、详情和删除评估；支持用户范围幂等键、每日限额、失败状态和知识版本引用。

完成标准：规则先执行；紧急结果不等待模型；模型无法降级；非法/超时/非 JSON/注入/禁用内容路径 fail-safe；评估历史追加且 A/B 用户隔离。没有专业批准规则时，生产评估保持 503/禁用，自动化测试使用明确标为测试用途的 Fake 规则。

### 阶段 F：隐私、审计、保留与内部边界

1. 实现不含正文的健康访问审计，并覆盖读、写、删、发布和失败解密。
2. 实现撤回同意、删除记录和用户注销清理契约；保留期清理支持 Dry Run 和可检查报告。
3. 导出 M07 公共知识检索 Facade，返回最小字段和版本来源；用测试证明无法传入或返回用户健康数据。
4. 实现旧数据 Dry Run 导入器：手机号到 `users.id` 映射、匿名/冲突隔离、旧结果加密保存为 legacy snapshot、旧知识导入草稿、重复运行幂等。
5. 默认不挂载旧路由；如实现兼容 Controller，必须由配置开启、忽略旧身份字段、标记 deprecated 且复用新 Service。

完成标准：审计无健康正文；删除/过期路径可验证；M07 只能见公共知识；导入报告能区分成功、跳过、冲突和非法 JSON。

### 阶段 G：用户前端迁移

1. 移除 `getUserId()`、手机号查询和请求体身份字段。
2. 将健康档案、测量时间序列、结构化症状和评估历史接入 V2 API。
3. 删除疾病概率和用药卡；新增就医紧迫度、下一步行动、警惕信号、知识来源、局限和 AI 显式标识。
4. 错误或非法响应显示“暂时无法评估”，不得默认 `low`、`stable` 或 `emergency=false`。
5. 紧急状态把 120 和立即求助操作置于结果顶部；不把模型文案当作紧急状态来源。
6. 实现易读的单独同意、撤回和本人记录删除入口，保持中老年用户可读性和低带宽可用性。

完成标准：类型中不存在旧危险字段或客户端身份；前端单元/组件/E2E 覆盖普通、信息不足、紧急、上游失败、撤回同意和跨用户不可达路径。

### 阶段 H：回归与收口

1. 补齐 Swagger、README、环境变量示例、数据迁移和运行说明；真实密钥不写入仓库。
2. 审查每个 Presenter，确保 Entity、密文、内部错误和审计信息不会被序列化。
3. 审查数据库索引、唯一约束、外键删除策略、Migration 正向/回滚和快照一致性。
4. 审查 M08、认证、用户、系统健康检查和前端其他入口回归。
5. 对照 `方案设计.md` 第 20 节逐条附上证据，未满足项保持未完成或外部审核状态。

## 7. 每项任务的执行循环

对每个 `M09-xxx` 执行同一个闭环：

1. 读取相关现有实现和测试，确认边界与共享改动。
2. 为核心规则先写失败测试；对纯装配或 Migration 至少先明确可检查断言。
3. 做满足当前任务的最小实现，使用现有 NestJS、MikroORM、class-validator、Zod、Guard、Presenter 和异常风格。
4. 运行最小定向测试；失败时定位根因并修复，不通过降低断言、吞异常或移除测试获得绿色。
5. 运行受影响模块的回归测试和类型检查。
6. 检查安全、所有权、日志、错误和 Migration 影响。
7. 记录证据并更新 `progress.md`，然后开始下一项。

保持实现直接、可读、单一职责。只有当当前代码中已经出现可证明的重复和稳定边界时才抽象共享基础设施；不要为未来 P2 构建框架。

## 9. 外部证据与完成状态

总体状态只能使用下列值：

- `IN_PROGRESS`：仍有可在当前工程环境继续完成的代码或自动化工作。
- `ENGINEERING_AND_AUTOMATION_COMPLETE`：工程 P0 已实现，自动化门禁通过；允许仍缺专业或真实环境验收。
- `EXTERNAL_ACCEPTANCE_PENDING`：工程工作已完成，但医学规则/知识审核、隐私法律确认、真实模型或生产环境验证尚缺必要外部证据。
- `PRODUCTION_ACCEPTANCE_PASSED`：只有用户提供或当前执行产生了可检查的专业审核、法律/隐私确认和真实环境证据，并且第 20 节全部满足时才可使用。

医学规则和知识发布至少需要可检查的审核人身份、资质/职责依据、规则或内容版本、审核日期和结论。没有这些证据时保持功能安全关闭，状态最多为 `EXTERNAL_ACCEPTANCE_PENDING`。

真实 LLM 验证只使用虚构、去标识化输入，记录 Provider、模型、Schema 版本、时间、结果和脱敏错误。没有真实凭据或网络时不得声称验证通过。

## 10. 阻塞处理

优先通过代码、现有文档、测试和保守可配置默认值推进。以下情况才停止并向用户请求方向：

- 两个方案会不可逆地改变数据归属或医疗安全边界，现有资料不能判断。
- 需要用户提供真实密钥、专业审核结论、法律确认或授权外部系统操作。
- 必须覆盖无法安全合并的用户现有改动。
- 数据迁移目标无法唯一确定，继续可能把健康数据归错用户。

遇到外部阻塞时，先完成不依赖该阻塞的端口、Unavailable Adapter、Fake、Fixture、自动化和文档；把阻塞集中记录，不让它阻塞整个模块。
