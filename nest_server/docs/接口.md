# 原后端接口清单

## 1. 文档说明

本文记录 `servers` 目录下 Express 后端的当前接口行为，用作 NestJS 重构前的基线，不代表推荐的新接口设计。

- 接口总数：38。
- 普通 JSON 接口：35。
- SSE 流式接口：2。
- 文本接口：1。
- 统计包含根路径健康响应 `GET /`。
- 路径、字段、状态码均以当前代码为准；历史文档与代码不一致时已在「现状备注」中说明。
- 文档不包含 CORS 自动处理的 `OPTIONS` 请求。

## 2. 基础约定

### 2.1 服务地址

默认监听：

```text
http://localhost:3000
```

端口可由环境变量 `PORT` 修改。

### 2.2 请求格式

除无请求体的查询接口外，普通请求使用：

```http
Content-Type: application/json
```

受保护接口使用：

```http
Authorization: Bearer <token>
```

### 2.3 鉴权类型

| 标记 | Token 来源 | JWT 载荷 | 有效期 |
| --- | --- | --- | --- |
| 公开 | 不需要 Token | — | — |
| 管理员 | 管理员登录接口返回的 `adminToken` | `id`、`role` | 24 小时 |
| 超级管理员 | 管理员 Token，且 `role = super_admin` | `id`、`role` | 24 小时 |
| 村民 | 村民登录接口返回的 `token` | `id`、`phone`、`name` | 24 小时 |

Token 缺失、格式不是 Bearer、校验失败或过期时，鉴权中间件返回：

```json
{
  "code": 401,
  "message": "未登录或 token 无效",
  "data": null
}
```

超级管理员角色不满足时返回 HTTP 403：

```json
{
  "code": 403,
  "message": "权限不足",
  "data": null
}
```

### 2.4 普通 JSON 响应

多数成功响应使用：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

当前代码没有历史《接口设计规范》中写到的 `success` 字段。个别接口即使业务失败也返回 HTTP 200，后文会逐项标注。

### 2.5 SSE 响应

SSE 事件格式：

```text
data: <JSON>

```

统一 Agent 可能返回：

```text
data: {"content":"文本片段"}

data: {"finished":true}

data: {"error":"AI 服务暂时不可用，请稍后重试。"}

```

旧版 AI 聊天正常情况下只返回 `content` 与 `finished`。

## 3. 常用数据结构

```json
{
  "adminID": "s01",

  "phone": "手机号",
  "role": "super_admin"
```

`role` 的代码已知值为 `super_admin`、`common_admin`。当前列表和登录响应会返回 `password`。

```json
  "id": 1,
```

## 5. 系统接口

### 01 `GET /`

- 鉴权：公开。
- 参数：无。
- 成功状态：HTTP 200。
- 响应类型：`text/html; charset=utf-8`，正文为 `Hello, World!`。
- 现状备注：只证明 Express 路由可响应，不检查数据库、Kimi 或 Open-Meteo 可用性。

## 6. 管理员认证接口

### 02 `POST /api/v1/admin/auth/register`

- 鉴权：公开。
- 请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `adminname` | string | 是 | 管理员名称，代码检查名称唯一 |
| `password` | string | 是 | 明文存储 |
| `role` | string | 是 | 只支持 `super_admin`、`common_admin`；其他值在生成 ID 时抛错 |
| `phone` | 任意 | 否 | 当前没有格式校验 |

- 成功：HTTP 201。

```json
{
  "code": 201,
  "message": "注册成功",
  "data": {
    "adminID": "s01"
  }
}
```

- 已实现错误：400 缺少必填字段；409 名称已存在；500 读取、ID 生成或写入失败。
- 现状备注：请求体对象会被直接追加到 JSON，除生成 `adminID` 外不会过滤额外字段；接口不要求已有管理员授权。

### 03 `POST /api/v1/admin/auth/login`

- 鉴权：公开。
- 请求体：`adminname`、`password`，均必填字符串语义，但未做类型校验。
- 成功：HTTP 200。

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "admin": "Admin 对象",
    "adminToken": "JWT"
  }
}
```

- 已实现错误：400 参数缺失；401 管理员不存在或密码错误；500 读取或签发 Token 失败。
- 现状备注：`admin` 包含明文密码。

## 7. 管理员管理接口

以下接口都要求有效管理员 Token，但不限制 `role`。

### 04 `GET /api/v1/admin/administrator/lists`

- 参数：无。
- 成功 `data`：`Admin[]`。
- 现状备注：返回全部管理员字段，包括密码；文件读取失败时存储层返回空数组，接口仍返回成功。

### 05 `DELETE /api/v1/admin/administrator/:id`

- 路径参数 `id`：管理员编号，例如 `s01`。
- 成功：HTTP 200，`data: null`。
- 不存在：HTTP 404，消息为「管理员不存在」。
- 现状备注：没有防止删除当前登录管理员或最后一个超级管理员。

### 06 `PUT /api/v1/admin/administrator/:id`

- 路径参数 `id`：路由声明存在，但实现没有读取它。
- 请求体：

| 字段 | 必填语义 | 当前用途 |
| --- | --- | --- |
| `adminID` | 实际必填 | 用于查找要修改的管理员 |
| `adminname` | 未校验 | 覆盖原值 |
| `password` | 未校验 | 覆盖原值 |
| `phone` | 未校验 | 覆盖原值 |
| `role` | 未校验 | 覆盖原值 |

- 成功：HTTP 200，`data: null`。
- 不存在：HTTP 404，消息为「管理员不存在」。
- 现状备注：路径 `:id` 与请求体 `adminID` 不一致时，以请求体为准；更新时不检查管理员名称重复，也不重新生成管理员编号。

## 8. 管理端文章接口

以下接口都要求有效管理员 Token，不限制管理员角色。

### 07 `POST /api/v1/admin/articles`

- 请求体：

| 字段 | 类型 | 必填 | 默认或处理 |
| --- | --- | --- | --- |
| `title` | string | 是 | 去除首尾空白后不能为空 |
| `content` | string | 是 | 去除首尾空白后不能为空 |
| `summary` | string | 否 | 默认空字符串 |
| `cover` | string | 否 | 默认空字符串 |
| `category` | string | 否 | 默认空字符串 |
| `isBanner` | boolean 或 `1` | 否 | 其他值转换为 `0` |
| `isTop` | boolean 或 `1` | 否 | 其他值转换为 `0` |
| `status` | 可转换为 number | 否 | 默认 `1`，未限制取值 |

- 成功：HTTP 200，消息「创建成功」，`data` 为创建后的 `Article`。
- 已实现错误：400 请求体、标题或内容错误；500 数据库异常。
- 现状备注：虽然是创建接口，成功状态不是 HTTP 201。

### 08 `PUT /api/v1/admin/articles/:id`

- 路径参数 `id`：严格正整数字符串，不接受 `01`。
- 请求体：字段与创建接口相同，均可选；标题和内容一旦传入就不能为空。
- 成功：HTTP 200，`data` 为更新后的 `Article`。
- 已实现错误：400 ID 或字段错误；404 文章不存在；500 数据库异常。
- 现状备注：空对象会返回原文章，不报错。

### 09 `DELETE /api/v1/admin/articles/:id`

- 路径参数 `id`：严格正整数字符串。
- 成功：HTTP 200，`data: { "id": 1 }`。
- 已实现错误：400 ID 错误；404 文章不存在；500 数据库异常。

### 10 `GET /api/v1/admin/articles`

- Query：

| 参数 | 类型 | 必填 | 默认或规则 |
| --- | --- | --- | --- |
| `page` | integer | 否 | 默认 1，必须大于等于 1 |
| `pageSize` | integer | 否 | 默认 15，范围 1～100 |
| `keyword` | string | 否 | 标题模糊匹配 |
| `category` | string | 否 | 分类精确匹配 |
| `status` | number 语义 | 否 | 精确匹配；未限制状态枚举 |

- 成功 `data`：

```json
{
  "list": ["Article"],
  "total": 1,
  "page": 1,
  "pageSize": 15
}
```

- 排序：`is_top DESC, create_time DESC`。
- 已实现错误：400 分页错误；500 数据库异常。

### 11 `GET /api/v1/admin/articles/:id`

- 路径参数 `id`：严格正整数字符串。
- 成功 `data`：`Article`，不限制发布状态。
- 已实现错误：400 ID 错误；404 文章不存在；500 数据库异常。

## 9. 后台村民管理接口

### 12 `GET /api/v1/admin/villagers/lists`

- Query：`page` 默认 1，`pageSize` 默认 15；使用 `parseInt`，没有最小值和最大值校验。
- 成功 `data`：

```json
{
  "list": ["User"],
  "total": 1,
  "page": 1,
  "pageSize": 15
}
```

- 现状备注：查询使用 `SELECT *`，列表包含密码；没有显式排序。

### 13 `DELETE /api/v1/admin/villagers/:id`

- 路径参数 `id`：直接传给 SQL，没有应用层正整数校验。
- 成功：HTTP 200，`data: null`，消息「OK」。
- 未删除任何行：HTTP 404，消息「未找到该村民信息」。

### 14 `PUT /api/v1/admin/villagers/:id`

- 路径参数 `id`：直接传给 SQL。
- 请求体字段：`name`、`phone`、`address`、`birthday`、`gender`、`password`。
- 成功：HTTP 200，`data: null`，消息「OK」。
- 未更新任何行：HTTP 404，消息「未找到该村民信息」。
- 现状备注：所有字段都会写入；没有字段校验、手机号冲突处理或部分更新语义。

## 10. 管理端人工客服接口

基础路径 `/admin/chat`。所有接口都要求管理员 Token 且角色必须为 `super_admin`。

### 15 `GET /admin/chat/conversations`

- 参数：无。
- 成功 `data`：

```json
[
  {
    "conversationId": 1,
    "userId": 10,
    "username": "村民姓名",
    "lastMessage": "最后消息或 null",
    "lastMessageTime": "数据库时间或 null",
    "unreadCount": 2
  }
]
```

- 排序：最后消息时间或创建时间倒序。
- 现状备注：左连接 `users`，用户不存在时 `username` 为空字符串。

### 16 `GET /admin/chat/conversations/:conversationId/messages/after`

- 路径参数 `conversationId`：严格正整数字符串。
- Query `lastMessageId`：必填，严格非负整数字符串；传 `0` 表示从头取。
- 成功 `data`：

```json
{
  "list": ["Message"],
  "latestMessageId": 123
}
```

- 无新消息时 `list` 为空，`latestMessageId` 等于请求值。
- 已实现错误：400 参数错误；404 会话不存在；500 数据库异常。

### 17 `GET /admin/chat/conversations/:conversationId/messages`

- 路径参数 `conversationId`：严格正整数字符串。
- 成功 `data`：`Message[]`，按 `created_at ASC, id ASC`。
- 已实现错误：400 参数错误；404 会话不存在；500 数据库异常。

### 18 `POST /admin/chat/conversations/:conversationId/messages`

- 路径参数 `conversationId`：严格正整数字符串。
- 请求体：`{ "content": "非空文本" }`，会去除首尾空白。
- 成功 `data`：

```json
{
  "id": 10,
  "conversationId": 1,
  "senderType": "admin",
  "content": "消息正文"
}
```

- 行为：在事务中插入消息，更新最后消息、最后消息时间和 `is_admin_read = 1`。
- 已实现错误：400 参数或内容错误；404 会话不存在；500 数据库异常。

### 19 `PATCH /admin/chat/conversations/:conversationId/read`

- 路径参数 `conversationId`：严格正整数字符串。
- 请求体：无。
- 成功 `data`：

```json
{
  "conversationId": 1,
  "unreadCount": 0,
  "isAdminRead": 1
}
```

- 行为：将 `unread_count` 设为 0、`is_admin_read` 设为 1。
- 已实现错误：400 参数错误；404 会话不存在；500 数据库异常。

## 13. 农业接口

基础路径中的 `argiculture` 是当前代码真实拼写。

### 24 `GET /api/v1/user/argiculture/info/:crop`

- 鉴权：村民。
- 路径参数 `crop`：作物名称或已收录别名；会去除空白并归一化。
- 请求体、Query：无。
- 行为：使用源码固定的长安区环境、模拟天气、模拟市场数据调用 Kimi，并把结果按作物和地区保存。
- 成功 `data`：

```json
{
  "cropName": "小麦",
  "text": "模型返回的 JSON 字符串",
  "analysisTime": "YYYY-MM-DD HH:mm:ss"
}
```

- 现状备注：`text` 是字符串，不是后端解析后的 JSON 对象；路由没有异常处理，模型或数据库错误交给 Express 默认错误流程。

### 25 `GET /api/v1/user/argiculture/info/db/:crop`

- 鉴权：村民。
- 路径参数 `crop`：会归一化作物名称。
- 成功 `data`：

```json
{
  "cropName": "小麦",
  "analysis": {
    "text": "最近分析文本或 null",
    "analysisTime": "数据库时间或 null"
  }
}
```

- 现状备注：只按作物名称查询，不按地区过滤；没有记录时仍返回 HTTP 200。

## 14. 健康接口

### 26 `POST /api/v1/user/healthy/info`

- 鉴权：村民。
- 请求体：

| 字段 | 类型 | 必填 | 默认值 |
| --- | --- | --- | --- |
| `userId` | string 语义 | 否 | `req.user.phone`，再退化为 `anonymous` |
| `basicInfo` | object 或 string | 否 | `{}` |
| `symptoms` | object 或 string | 否 | `{}` |
| `habits` | object 或 string | 否 | `{}` |
| `medicalHistory` | object 或 string | 否 | `{}` |

- 行为：调用 Kimi，解析 JSON，按 `userId` 新增或更新健康分析。
- 成功 `data`：

```json
{
  "userId": "用户标识",
  "analysis": {
    "riskLevel": {},
    "possibleDiseases": [],
    "explanation": [],
    "medicationSuggestions": [],
    "medicalAdvice": [],
    "lifestyleSuggestions": [],
    "warningSignals": [],
    "needHospital": false,
    "emergency": false,
    "summary": {}
  },
  "analysisTime": "YYYY-MM-DD HH:mm:ss"
}
```

- 失败：HTTP 500，消息「健康分析生成失败」，`data: {}`。
- 现状备注：请求体 `userId` 可覆盖 JWT 中的手机号；代码只要求模型返回可解析 JSON，没有按 Prompt 中的完整结构做运行时校验。

### 27 `GET /api/v1/user/healthy/info/db/:userId`

- 鉴权：村民。
- 路径参数 `userId`：直接用于查询，没有与 JWT 身份比较。
- 成功 `data`：

```json
{
  "userId": "请求中的用户标识",
  "analysis": {
    "analysis": "已解析的健康分析对象",
    "analysisTime": "数据库时间"
  }
}
```

- 没有记录时：`data.analysis` 为 `null`。
- 数据库或 JSON 解析失败：HTTP 500，消息「健康分析查询失败」。

## 15. 村民资料接口

### 28 `PUT /api/v1/user/info/:id`

- 鉴权：村民。
- 路径参数 `id`：用户表主键，直接传给 SQL，没有与 JWT 的 `req.user.id` 比较。
- 请求体：`name`、`phone`、`address`、`birthday`、`gender`、`password`。
- 成功：HTTP 200，消息「已更新完成」，`data: {}`。
- 未更新任何行：HTTP 404，消息「更新失败」，`data: {}`。
- 现状备注：是全字段覆盖更新，不支持安全的部分更新语义。

### 29 `POST /api/v1/user/info/healthy`

- 鉴权：村民。
- 请求体：`{ "phone": "作为 health_analysis.user_id 查询的值" }`。
- 成功：HTTP 200。
- 有记录时 `data`：

```json
{
  "analysis": "已解析的健康分析对象",
  "analysisTime": "数据库时间"
}
```

- 无记录时 `data: {}`。
- 现状备注：使用请求体手机号，不使用 JWT 手机号；没有异常处理。

## 16. 公开文章接口

### 30 `GET /api/v1/articles/banner`

- 鉴权：公开。
- 参数：无。
- 成功 `data`：最多 5 条 `Article`。
- 筛选：`status = 1 AND is_banner = 1`。
- 排序：置顶优先、创建时间倒序。

### 31 `GET /api/v1/articles`

- 鉴权：公开。
- Query：

| 参数 | 必填 | 默认或规则 |
| --- | --- | --- |
| `page` | 否 | 默认 1，必须大于等于 1 |
| `pageSize` | 否 | 默认 15，范围 1～100 |
| `category` | 否 | 分类精确匹配 |

- 成功 `data`：`{ list: Article[], total, page, pageSize }`。
- 固定只查询 `status = 1` 的文章。
- 已实现错误：400 分页错误；500 数据库异常。

### 32 `GET /api/v1/articles/:id`

- 鉴权：公开。
- 路径参数 `id`：严格正整数字符串。
- 成功 `data`：已发布的 `Article`。
- 行为：返回详情前执行 `views = views + 1`。
- 已实现错误：400 ID 错误；404 文章不存在或未发布；500 数据库异常。
- 现状备注：响应对象在增加浏览量之前已读取，因此本次返回的 `views` 是旧值。

## 17. 统一智能 Agent 接口

### 33 `POST /api/agent`

- 鉴权：村民。
- 请求体：

```json
{
  "message": "玉米叶子发黄怎么办"
}
```

- `message` 必须是去除首尾空白后的非空字符串。
- 参数错误：在建立 SSE 前返回 HTTP 400 普通 JSON。

```json
{
  "code": 400,
  "message": "message 不能为空",
  "data": null
}
```

- 成功响应头：

```http
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
```

- 文本事件：`data: {"content":"片段"}`。
- 完成事件：`data: {"finished":true}`。
- 流内错误事件：`data: {"error":"AI 服务暂时不可用，请稍后重试。"}`，随后关闭连接。
- 工具选择：农业问题查询农业知识与历史分析；健康问题查询健康知识与历史分析；天气问题调用 Open-Meteo；其他问题由模型直接回答。
- 现状备注：接口不保存多轮历史，也不使用 JWT 中的用户身份做领域数据隔离；流建立后的错误不会改成非 200 HTTP 状态。

## 18. 村民端人工客服接口

以下接口都要求村民 Token，用户 ID 只从 `req.user.id` 获取。

### 34 `GET /api/chat/conversation`

- 参数：无。
- 行为：查询当前用户最早的会话；不存在时自动创建。
- 成功 `data`：

```json
{
  "conversationId": 1,
  "status": "active",
  "unreadCount": 0
}
```

- 数据库中的 `open` 状态会转换为 `active`，其他状态原样返回。
- 已实现错误：401 Token 中用户 ID 无效；500 数据库异常。

### 35 `GET /api/chat/messages/latest`

- Query `lastMessageId`：必填，严格非负整数字符串；`0` 表示查询所有 `id > 0` 的消息。
- 行为：必要时自动创建当前用户会话。
- 成功 `data`：`Message[]`，只含 `id > lastMessageId` 的消息，按 ID 升序。
- 已实现错误：400 参数错误；401 用户身份无效；500 数据库异常。

### 36 `GET /api/chat/messages`

- 参数：无。
- 行为：必要时自动创建当前用户会话。
- 成功 `data`：`Message[]`，按 `created_at ASC, id ASC`。
- 已实现错误：401 用户身份无效；500 数据库异常。

### 37 `POST /api/chat/messages`

- 请求体：`{ "content": "非空文本" }`，会去除首尾空白。
- 行为：必要时自动创建会话；在事务中插入 `sender_type = user` 的消息并更新会话。
- 成功 `data`：

```json
{
  "id": 10,
  "senderType": "user",
  "content": "消息正文",
  "createdAt": "数据库时间",
  "conversationId": 1
}
```

- 会话更新：最后消息、最后消息时间、更新时间、`unread_count + 1`、`is_admin_read = 0`。
- 已实现错误：400 内容为空；401 用户身份无效；500 数据库异常。

### 38 `PATCH /api/chat/read`

- 请求体、Query：无。
- 行为：必要时自动创建会话，将 `unread_count` 设为 0。
- 成功 `data`：

```json
{
  "conversationId": 1,
  "unreadCount": 0
}
```

- 已实现错误：401 用户身份无效；500 数据库异常。

## 19. 仅内部能力，不是 HTTP 接口

以下能力存在于源码，但没有单独对外路由，不能算入 38 个 HTTP 接口：

| 内部能力 | 调用方 | 说明 |
| --- | --- | --- |
| `agricultureService.search(question)` | 统一 Agent | 查询农业知识与历史农业分析，各最多 5 条 |
| `healthService.search(question)` | 统一 Agent | 查询健康知识与全部用户历史健康分析，各最多 5 条 |
| `weatherService.getWeather(city)` | 统一 Agent | 查询 Open-Meteo，默认城市为西安 |
| 公共 MySQL `transaction` | 人工客服 | 保证消息写入与会话更新同一事务 |
| `requireRole(...roles)` | 管理端人工客服 | 当前只有 `super_admin` 检查在使用 |

## 20. 接口层现状问题汇总

这些是重构时需要保留证据、再决定是否兼容的现状，不是本阶段的代码修改项。

1. 管理员和村民密码均明文存储，多个接口会把密码返回给调用方。
2. 管理员 JWT、村民 JWT 的密钥硬编码在源码中。
3. 管理员注册公开，并允许请求方选择角色。
4. `PUT /api/v1/admin/administrator/:id` 忽略路径 ID。
5. 村民资料和健康查询接口没有校验资源是否属于当前 JWT 用户。
6. 健康 Agent 工具可能检索并暴露其他用户的健康分析。
7. 村民注册、登录的业务失败仍返回 HTTP 200 和 `code: 200`。
8. 内联路由与 Controller 路由的异常响应不统一。
9. 存在两套 AI 聊天接口，鉴权后的身份使用方式和历史保存方式不同。
10. `/api/v1/user/argiculture` 是已上线代码中的拼写，重构时是否兼容需要确认。
11. 管理端人工客服路径 `/admin/chat` 与其他管理接口的版本前缀不一致。
12. 公开文章详情返回的浏览量是本次自增前的值。
13. 农业、健康知识表只有查询能力，没有录入、修改、删除接口。
14. 数据表没有外键，一个村民一个会话也没有数据库唯一约束。
