# 用户聊天接口文档

## 基础信息

基础路径：

```txt
/api/chat
```

鉴权方式：

```txt
Authorization: Bearer <userToken>
```

用户身份：

```txt
后端从 JWT 中的 req.user.id 获取用户 ID
前端禁止传 userId
```

统一响应格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

常见错误：

| HTTP 状态码 | 说明 |
| --- | --- |
| 400 | 参数错误 |
| 401 | 未登录或 token 无效 |
| 500 | 服务端异常 |

## 1. 获取当前用户会话

```txt
GET /api/chat/conversation
```

说明：获取当前登录用户与村委会的会话。如果会话不存在，后端会自动创建。

请求头：

```txt
Authorization: Bearer <userToken>
```

响应示例：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "conversationId": 1,
    "status": "active",
    "unreadCount": 2
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| conversationId | number | 当前用户会话 ID |
| status | string | 会话状态，数据库 open 会返回为 active |
| unreadCount | number | 当前会话未读数量 |

## 2. 获取聊天记录

```txt
GET /api/chat/messages
```

说明：获取当前登录用户自己的聊天记录。后端只会查询当前用户对应会话，前端不需要也不能传 `userId`。

排序：

```txt
created_at ASC, id ASC
```

响应示例：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": [
    {
      "id": 1,
      "senderType": "user",
      "content": "您好",
      "createdAt": "2026-06-10 12:00:00"
    },
    {
      "id": 2,
      "senderType": "admin",
      "content": "您好，请问有什么需要帮助的？",
      "createdAt": "2026-06-10 12:01:00"
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | number | 消息 ID |
| senderType | string | 发送方，user 或 admin |
| content | string | 消息内容 |
| createdAt | string | 消息创建时间 |

## 3. 用户发送消息

```txt
POST /api/chat/messages
```

说明：当前登录用户向村委会发送咨询消息。

请求体：

```json
{
  "content": "您好，我想咨询农业补贴"
}
```

请求体字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| content | string | 是 | 消息内容，不能为空字符串 |

响应示例：

```json
{
  "code": 200,
  "message": "发送成功",
  "data": {
    "id": 10,
    "senderType": "user",
    "content": "您好，我想咨询农业补贴",
    "createdAt": "2026-06-10 12:02:00",
    "conversationId": 1
  }
}
```

后端行为：

- 自动获取或创建当前用户会话。
- 新增一条 `sender_type = user`、`message_type = text` 的消息。
- 更新会话：
  - `last_message`
  - `last_message_time`
  - `updated_at`
  - `unread_count = unread_count + 1`
  - `is_admin_read = 0`
- 消息插入和会话更新在同一个 SQLite transaction 中完成。

## 4. 增量获取新消息

```txt
GET /api/chat/messages/latest?lastMessageId=100
```

说明：用于前端轮询。只返回当前用户会话中 `id > lastMessageId` 的消息，禁止用它获取全量聊天记录。

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| lastMessageId | number | 是 | 前端已知的最后一条消息 ID，必须是非负整数。传 0 表示获取 id > 0 的消息 |

响应示例：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": [
    {
      "id": 101,
      "senderType": "admin",
      "content": "您好，请问是哪种补贴",
      "createdAt": "2026-06-10 12:03:00"
    }
  ]
}
```

无新消息响应：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": []
}
```

前端轮询建议：

1. 进入聊天页面时先调用 `GET /api/chat/conversation`，确保会话存在。
2. 再调用 `GET /api/chat/messages` 获取全量历史消息。
3. 记录当前消息列表最后一条消息的 `id`，作为本地 `lastMessageId`。
4. 定时调用本接口，将本地 `lastMessageId` 作为 Query 参数。
5. 如果返回数组不为空，将新消息追加到页面，并把本地 `lastMessageId` 更新为返回数组最后一条消息的 `id`。
6. 不要在本接口参数缺失时降级调用全量接口，否则会造成重复消息。

## 5. 标记已读

```txt
PATCH /api/chat/read
```

说明：用户进入聊天页面后调用，将当前用户会话的未读数量清零。

响应示例：

```json
{
  "code": 200,
  "message": "标记已读成功",
  "data": {
    "conversationId": 1,
    "unreadCount": 0
  }
}
```

前端使用建议：

- 用户进入聊天页面并成功加载会话后调用一次。
- 用户停留在聊天页面时，如果需要实时已读效果，可在收到管理员新消息后再次调用。

## 推荐页面初始化流程

```txt
1. GET /api/chat/conversation
2. GET /api/chat/messages
3. PATCH /api/chat/read
4. 启动轮询：GET /api/chat/messages/latest?lastMessageId=<最后一条消息ID>
5. 用户发送消息：POST /api/chat/messages
6. 页面卸载时停止轮询
```
